# Honeypot 项目目录规划

## 当前结构与目标结构

```text
honeypot/
├── backend/
│   ├── src/
│   │   ├── Honeypot.Shared/              # ApiResult、DTO、枚举、事件合同
│   │   ├── Honeypot.Engine/              # 风险评分、规则、威胁聚合
│   │   ├── Honeypot.Protocol.Abstractions/ # 适配器、会话、能力和校验接口
│   │   ├── Honeypot.Runtime/              # ListenerHost、端口、SessionManager
│   │   ├── Honeypot.Protocols.Ssh/        # SSH 适配器
│   │   ├── Honeypot.Protocols.MySql/      # MySQL 适配器
│   │   ├── Honeypot.Protocols.Mongo/      # MongoDB 适配器
│   │   ├── Honeypot.Protocols.MsSql/      # MSSQL 适配器
│   │   ├── Honeypot.Protocols.Rdp/        # RDP 适配器
│   │   ├── Honeypot.Protocols.<Name>/     # 其他数据库与系统协议，参见扩展方案
│   │   ├── Honeypot.Persistence/          # 事件、威胁、配置和审计存储
│   │   └── Honeypot.Api/                  # 管理 API、认证、RBAC、审计查询
│   └── tests/                             # 单元、协议回放、API 合同和集成测试
├── frontend/                              # Ant Design Pro 管理台
├── sensors/                               # 采集器与传感器部署边界
├── rules/                                 # 规则集、样本和版本治理
├── docs/{requirements,spec,api,releases,adr}/
├── deploy/                                # 隔离环境与发布说明
└── scripts/                               # 构建、回放、验证和文档检查
```

当前仓库已实现 `Honeypot.Shared`、`Honeypot.Protocol.Abstractions`、`Honeypot.Runtime`、首批 `Honeypot.Protocols.*`、`Honeypot.Engine` 和 `Honeypot.Api` 的首期闭环；生产持久化、管理认证和更高拟真等级需要按一期方案继续建立。

## 模块职责

- **Shared**：不依赖 ASP.NET Core，定义 `ApiResult<T>`、服务配置、事件、威胁和 ID 合同。
- **Engine**：不读取网络或数据库，负责规则匹配、风险评分、威胁聚合和幂等重放。
- **Protocol.Abstractions**：定义适配器、会话、能力描述、配置校验和事件接收接口。
- **Runtime**：统一监听 TCP/UDP、端口冲突、连接限流、超时、会话生命周期和配置热重载。
- **Protocols.<Name>**：只处理对应协议的 banner、握手、认证和有限交互，不自行开端口或写库。
- **Persistence**：实现事件可靠队列/WAL、事件流、威胁档案、配置版本、证据索引和审计。
- **Api**：负责服务类型、人格、实例、监听、连接、事件、威胁和运行指标接口。
- **Frontend**：只做管理视图和 API 调用，服务端鉴权是最终边界。

## 连接事件链路

```text
ListenerHost accept
  → ConnectionAccepted 立即记录
  → ThreatIpProfile 聚合
  → ProtocolAdapterSession
  → Handshake / Auth / Rule / Close 事件
  → 指标、审计和查询
```

监听器必须记录目标端口、实例和 listenerId；否则无法区分同一协议多个伪端口的探测行为。

## 目录约定

实体和 DTO 放 `Models/`，接口放 `Service/`，实现放 `Service/impl/`，公共代码放 `Common/`，配置放 `Options/`，中间件放 `Middleware/`，后台任务放 `Workers/`，持久化和迁移放 `Data/`。协议回放样本放适配器测试目录或隔离样本目录，不散落在生产配置中。
