# 数据库与系统适配器扩展方案

- 日期：2026-11-10。
- 状态：已按本文范围完成实施，约定客户端验证与未验证项见本文第七节。
- 范围：新增 PostgreSQL、Redis、Oracle、Db2、Memcached、HBase、InfluxDB、Elasticsearch，以及 Telnet、SMB、NFS，共 11 类适配器。
- 目标：对约定的真实客户端完成必要协商、接收实际认证材料，返回该协议的正常认证失败；没有密码登录概念的协议返回真实的认证或访问拒绝。保持 AlwaysFail，不提供 shell、数据库执行、文件共享或文件系统内容。

## 1. 默认名称、端口与页面归组

平台显示名称使用产品通用名称；内部 ID 保持 `<adapterKey>-default`。平台实例名、数据库实例名、SID、serviceName、数据库名分别处理，不声称所有厂商都有固定的默认实例名称。

| 页签 / 分组 | 显示名称 | adapterKey | 新建实例默认 TCP 端口 | 选定范围 |
| --- | --- | --- | --- | --- |
| 数据库 | PostgreSQL | postgresql | 5432 | PostgreSQL 协议 3.x，SCRAM-SHA-256 为默认认证人格 |
| 数据库 | Redis | redis | 6379 | RESP2/RESP3，密码和 ACL 用户认证 |
| 数据库 | Oracle | oracle | 1521 | 先按 19c 普通用户认证交换验收；服务名可配置 |
| 数据库 | IBM Db2 | db2 | 50000 | Db2 LUW；Linux/UNIX 实例人格采用 db2inst1 |
| 数据库 | Memcached | memcached | 11211 | binary SASL PLAIN 认证人格 |
| 数据库 | HBase | hbase | 16020 | 原生 RegionServer RPC/SASL，不用 HTTP 网关替代 |
| 数据库 | InfluxDB | influxdb | 8086 | 分别配置 v1/v2 人格；不混用 v3 Core 的 8181 端口及行为 |
| 数据库 | Elasticsearch | elasticsearch | 9200 | REST 认证；不是 9300 节点传输协议 |
| 系统 / Linux | Telnet | telnet | 23 | Linux 风格交互登录 |
| 系统 / Windows | SMB | smb | 445 | SMB2/3，SPNEGO/NTLM；不包含 SMB1/NetBIOS 139 |
| 系统 / Linux | NFS | nfs | 2049 | 首批 NFSv4.1 / TCP、AUTH_SYS；RPCSEC_GSS 按实际支持范围标注 |

Windows/Linux 是管理台归组，不表示协议只能在对应系统使用。系统页改为每组包含多张适配器卡片；数据库页保留原有 MySQL、MSSQL、MongoDB 并加入八类。

现有实例名称和绑定端口保留。新建数据库实例统一使用惯用端口，包括现有类型的新建默认值 MySQL 3306、MSSQL 1433、MongoDB 27017。端口冲突明确提示，不再静默加一；同一地址发生端口占用时，需要先调整绑定才能启动。新适配器默认停止，不因升级自动暴露新端口。

## 2. 认证交换与可采集材料

| 协议 | 计划实现的认证路径 | 客户端正常失败目标 | 证据边界 |
| --- | --- | --- | --- |
| PostgreSQL | Startup、SSLRequest/TLS、SCRAM-SHA-256 往返；另设 password/MD5 兼容人格，严格匹配客户端允许的机制 | ErrorResponse，SQLSTATE 28P01 | SCRAM/MD5 记录挑战响应；password 路径记录实际密码，不强制降级客户端策略 |
| Redis | RESP 数组/内联解析、AUTH password、AUTH username password、HELLO AUTH；未认证命令受控拒绝 | WRONGPASS；未提交认证时为 NOAUTH | 真实提交的用户名、密码；单参数 AUTH 对应 default 用户 |
| Oracle | Oracle Net/TNS、TTC 能力和认证参数交换；收到客户端认证材料后失败 | ORA-01017 | 按实际认证算法记录账号、服务与加密材料；不能承诺任意现代认证密码可恢复 |
| Db2 | DRDA EXCSAT、ACCSEC、SECCHK 等协商及认证拒绝；覆盖现代 JCC 默认加密机制和明确的兼容机制 | SECCHKCD 0x0f；JCC 为 -4214 / SQLSTATE 28000，CLP 表述另行验收 | 机制 3 密码及机制 9 加密协商分别验证；不能把密文显示为密码 |
| Memcached | binary 头、有界消息、SASL 机制枚举、PLAIN 提交 | 认证失败状态 0x20 | SASL PLAIN 用户名、密码；普通无认证客户端没有密码可记录 |
| InfluxDB | 版本对应的 HTTP 路由、挑战和响应；v1 Basic / u,p；v2 Token 及对应接口实际支持的认证 | 对应版本 HTTP 401 | 密码与 Token 分开；查询参数中的口令不得进入普通 URL 日志 |
| Elasticsearch | HTTP/HTTPS REST、产品识别、Basic / API key / Bearer、对应版本挑战头与 JSON 错误体 | HTTP 401 / security_exception | Basic 记录密码；API key、Bearer 按各自材料类型保存 |
| Telnet | NVT/IAC 协商、行输入、换行/退格、密码不回显、有限重复尝试 | login: → Password: → Login incorrect | 可记录实际用户名密码；提示属于 Linux 登录人格，不伪造标准数字失败码 |
| SMB | NEGOTIATE、SESSION_SETUP、SPNEGO/NTLM Type1→Type2→Type3；正确处理 SMB3.1.1 协商及预认证完整性 | STATUS_LOGON_FAILURE | 用户名、域、工作站、挑战响应；NTLM 不传输明文密码 |
| HBase | 原生 RPC 前导、SASL、delegation-token DIGEST-MD5 交换及失败；Kerberos 按真实前提验收 | 原生 SASL 认证失败 | Token 身份、挑战响应或实际票据；没有普通密码字段 |
| NFS | ONC RPC record marking/XDR、NULL/COMPOUND、v4.1 必要协商；AUTH_SYS 访问请求合法拒绝 | 依据请求阶段返回规范的 RPC/NFS 访问或认证拒绝，例如 NFS4ERR_ACCESS | 主机、UID/GID、组、认证类型及实际请求；不能把 UID 当已验证用户名或密码 |

### 必须明确的兼容边界

1. “和真的一样”以列明版本、认证方式和真实客户端矩阵为验收口径，不能承诺所有版本、所有安全策略均显示相同文字。TLS 信任、NTLM 禁用或机制策略可能在密码提交前失败，不能用关闭客户端安全策略掩盖问题。
2. Oracle、Db2 必须走到认证材料提交再返回认证错误。首包发固定错误、超时、断线、TLS/DRDA/TNS 格式错误均不算认证验收通过。
3. Memcached 本批选择 binary SASL 模式；不是宣称所有 Memcached 安装默认开启密码认证，不包含上游实验性 ASCII 认证。
4. HBase 原生 Kerberos 登录依赖客户端有效凭据，错误密码可能在 KDC 阶段失败而完全不到达蜜罐。无真实 HBase/KDC 时，可用受控 delegation token 验证原生 SASL 失败；不能将 HTTP Basic 伪装成原生 HBase 登录。
5. NFS 的 AUTH_SYS 没有密码登录。此路径记录不可信的调用方身份并返回访问拒绝，不伪称密码错误或成功验证身份。RPCSEC_GSS 票据仅按实际接收内容存证；没有 KDC/服务身份前提时，不宣称完整 Kerberos 互认证。NFSv3 另涉及 rpcbind/mountd 等端口，不含在首批 v4.1 范围。
6. 不为提高明文采集率破解、猜测密码或把响应/票据标成密码。密码列及 Excel 延续“有实际密码直接显示，没有留空”，原始材料保留在加密证据详情。

## 3. 实现落点与复用

- 在 `backend/src/Honeypot.Protocols.<Name>/` 分协议实现，统一注册到 `Honeypot.Protocols.Builtin`。适配器不自行监听、不连接真实上游、不访问宿主 shell。
- 在 `ServiceAdapterDescriptor` 增加兼容性的分类、默认实例名、默认端口和人格元数据，通过现有 service-types API 返回，前端消费同一来源，消除多份硬编码。
- 复用 `ProtocolAdapterBase.RecordAuthenticationAsync`、`ProtocolTls`、NTLM 公共实现、会话预算和现有 MySQL 认证链路。HTTP 类适配器共享有界解析，覆盖请求头/体大小、Content-Length、传输编码、keep-alive 和取消，不另外开放管理 API 端口。
- 复用现有 `ServiceProfile` / `ProfileJson` 承载有默认值的人格参数，本批不需要 SQLite schema 迁移。厂家数据库实例/服务名称与平台实例名称使用不同字段。
- 使用现有事件、证据读取权限、审计、留存、Excel 详情链路；密码只进入加密证据和已授权的证据展示/导出，不进入普通事件、SignalR、异常或请求 URI 日志。
- 一次真实认证提交对应一条认证行为，协商步骤进入详情。同一连接的不同密码尝试分别记录。NFS 的访问拒绝单独按访问事件表达，补齐投影、威胁统计和中英文文案，不虚增认证次数。
- 不把用户名不存在、票据身份不可读取等情况伪造成已识别账号。Token、API key、challenge response 使用真实材料类型。

## 4. 实施顺序与验证

按以下顺序推进，11 类均保留在总范围内；某协议未通过真实客户端验收时，明确列为未验证，不因其它协议通过而宣称全部完成。

1. 统一默认元数据、系统多卡片分组、数据库分类、端口冲突提示与证据合同回归。
2. PostgreSQL、Redis、Telnet、Memcached 并行实现及真实客户端验证。
3. InfluxDB、Elasticsearch 共用 HTTP 处理；SMB 复用 NTLM；逐项进行客户端验收。
7. Oracle、Db2 原生驱动兼容；HBase 原生 SASL 和 NFSv4.1 访问拒绝按上述边界实现及验证。
5. 全量回归、说明已验收版本与限制，再准备服务器发布包。

验证矩阵：

- PostgreSQL：Npgsql / psql；Redis：redis-cli / StackExchange.Redis。
- Memcached：支持 binary SASL 的真实客户端；InfluxDB v1/v2：对应官方 SDK；Elasticsearch：对应官方客户端，不仅验证 curl 的 401。
- Oracle：指定版本 JDBC Thin 或官方驱动；Db2：JCC（覆盖 4.33+ 默认认证差异），可用时补 CLP。
- Telnet：真实 Telnet 客户端；SMB：smbclient 及可用的 Windows 客户端，明确 dialect 和默认安全策略。
- HBase：官方 RPC/SASL 客户端和受控 token；Kerberos 部分缺少条件则注明未验证。
- NFS：先用真实用户态 NFS 客户端验证合法访问拒绝；系统 mount 验证若需宿主挂载/权限调整，另行说明，不默认修改宿主。
- 公共检查：空密码、非 ASCII、分片/合包、超长与截断、未知机制、超时/取消、重复尝试、证据不可写、关联 ID、无明文泄露、读取权限、过期与 Excel 字段。
- 仅使用隔离回环地址和临时高端口进行本地测试；不占用宿主 23/445 等真实服务端口，不启动真实数据库或文件服务，不安装全局依赖。

实施完成后在发布说明中列出实际运行的构建与客户端验证结果。无法运行的真实客户端检查必须单独列出，不用构造报文测试替代验收。

## 5. 发布与回滚边界

- 当前实施本地代码与测试，不自动部署。用户要求部署时再按既有流程发布；新协议需后端更新，不能仅热替换前端文件。
- 发布前记录现有监听器配置与运行状态、准备旧版本回滚入口；沿用已有发布保留方式，不删除旧包。
- 现有事件/威胁/证据仍为内存实现，后端重启会丢失本进程数据和登录会话；本次扩展不把此现状称作持久化已完成。
- 不修改 .env、现有密钥/token、数据库结构，不执行 Git 操作。新实例默认停止，新增防火墙放行、公网端口或宿主权限变更不隐含在本地实施中。
