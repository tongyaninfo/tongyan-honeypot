# 一期实施方案

## 1. 一期目标

一期交付“单机、TCP、多端口、可扩展适配器、连接即时记录、IP 威胁聚合”的最小闭环。协议拟真以可验证等级为准，先完成 SSH、MySQL、MongoDB 的 L1/L2，再安排 RDP、MSSQL 的握手实验和兼容性验证。

## 2. 交付顺序

### P0：运行时和事件闭环

- 建立 `Protocol.Abstractions`、`Runtime` 和适配器注册表。
- 实现 `ServiceProfile`、`ServiceInstance`、`ListenerBinding` 的配置合同。
- 实现 TCP listener、端口冲突检测、启停、重载、连接上限、超时和指标。
- TCP accept 后生成 `ConnectionAccepted`，进入可靠队列或 SQLite WAL。
- 实现 `ThreatIpProfile`、事件幂等、风险评分和威胁查询 API。
- 管理面与诱捕端口分离，完成最小管理员认证和操作审计设计。

### P1：首批协议适配器

- SSH：版本交换、KEXINIT、认证尝试解析和受控拒绝。
- MySQL：Initial Handshake、能力位、auth plugin 和受控认证错误。
- MongoDB：hello/isMaster、buildInfo 和受控认证响应。
- 每个适配器配套正常、畸形、慢速、超时、超限和回放样本。
- 管理台接入服务实例、端口、连接、事件和威胁清单页面。

### P2：复杂协议兼容

- MSSQL：TDS PreLogin、有限 Login 响应和 `sqlcmd` 阶段性验证。
- RDP：TPKT/X.224、TLS/NLA/CredSSP 分阶段验证，目标是 `mstsc` 到达握手或凭据阶段后受控结束。
- 增加拟真人格配置、客户端兼容性矩阵和证据详情。

### P3：扩展能力

- SSE/WebSocket 实时事件流；
- 适配器受信插件包和版本管理；
- 多节点 Sensor Agent 注册；
- 告警通道、威胁情报联动和受控自动阻断；
- 更高等级的有限交互，不执行真实命令或 SQL。

## 3. 业务数据持久化原则

蜜罐业务记录、已保存的配置、任务历史和业务审计应在进程重启或容器重建后仍可查询或恢复。成功接收的业务事件必须写入持久存储；列表或报表是可从已保存记录重建的派生结果时，可以按需计算。持久化不等于永久保留，按数据类别约定留存期、磁盘上限、备份和恢复方式。

| 数据范围 | 当前实现与处理方式 |
| --- | --- |
| 实例、拟真配置、监听绑定与重启策略 | 已存 SQLite；进程启动时按已保存的期望状态和自动启动策略重新绑定，不恢复旧连接。 |
| 管理账号、角色与已生效的登录锁定 | 已存数据目录下的受控文件，管理账号只保存密码摘要。管理登录会话沿用重启后失效的行为。 |
| 报告、邮件通知与历史运行指标 | 已存报告事实、资源与监听采样、发件任务、发送尝试和已进入发件流程的报告快照；SMTP 密文与调度配置另存受控文件。即时报表预览按已保存事实生成。 |
| MCP 与 IP 归属地配置 | MCP 开关、API Key 摘要、权限和调用审计已存 SQLite；IP 数据源配置和地图落点缓存已保存至数据目录。来源归属地按当前数据源重查。 |
| 详细事件、威胁档案、认证证据、密码簿和证据访问审计 | 已实现 SQLite 持久化。查询密码簿从仍有效且已确认的证据统计。详见[持久化实施方案](连接事件与威胁清单设计.md#11-详细事件威胁档案与密码簿持久化)。 |
| 关键管理操作审计 | SQLite 保存首次初始化、管理登录和退出、业务配置变更与实例操作的结构化结果。管理员可分页查询。 |

活动 TCP/SignalR 连接、进程限流计数、实时推送队列、可重新查询的缓存和未提交的界面输入属于运行状态；业务历史通过已保存的事件、任务和采样查询，不承诺重启时恢复这些运行状态。后续如果把某项指标或归属地结果用于历史取证，应先定义如何保存当时的值和数据来源。

Syslog 日志正文和查询历史由第三方日志系统保存。现有投递目标配置和有界重发暂存继续沿用；本机业务库不复制 Syslog 报文或通用 HTTP 访问日志。

单机继续使用现有 SQLite 和受控数据目录。认证材料按字段白名单与大小上限采集，原文仅以密文保存；ID 沿用统一发号入口。新增数据库结构、部署密钥、迁移、备份与恢复范围需在实施前确认。

## 4. 一期验收

- SSH 实例绑定 22/2222，两个端口都能握手，事件标记准确端口。
- TCP connect 后不发送数据即断开，仍能查询 `ConnectionAccepted`。
- 同一 IP 访问多个服务时，威胁档案只生成一条并保留服务/端口明细。
- 重复事件不重复增加计数，重启后不重复监听。
- 端口冲突、权限不足、握手超时、超大帧、连接超限和适配器异常可观测且有明确结果。
- 事件写入故障时展示队列、降级、丢弃/补偿和最后成功时间。
- SSH、MySQL、Mongo 完成约定 L1/L2 验证；RDP/MSSQL 只按已完成的阶段记录结果。

## 5. 明确不做

当前不开放公网监听，不连接真实数据库或桌面，不代理内部服务，不执行客户端命令，不自动修改宿主防火墙，不把 mock、静态页面或单次 telnet 连接当作协议兼容验收。
