# 一期实施方案

## 1. 一期目标

一期交付“单机、TCP、多端口、可扩展适配器、连接即时记录、IP 威胁聚合”的最小闭环。协议拟真以可验证等级为准，先完成 SSH、MySQL、MongoDB 的 L1/L2，再安排 RDP、MSSQL 的握手实验和兼容性验证。

## 2. 交付顺序

### P0：运行时和事件闭环

- 建立 `Protocol.Abstractions`、`Runtime` 和适配器注册表。
- 实现 `ServiceProfile`、`ServiceInstance`、`ListenerBinding` 的配置合同。
- 实现 TCP listener、端口冲突检测、启停、重载、连接上限、超时和指标。
- TCP accept 后生成 `ConnectionAccepted`，进入可靠队列或 SQLite WAL。
- 实现 `ThreatIpProfile`、事件幂等、风险评分和威胁查询 API。
- 管理面与诱捕端口分离，完成最小管理员认证和操作审计设计。

### P1：首批协议适配器

- SSH：版本交换、KEXINIT、认证尝试解析和受控拒绝。
- MySQL：Initial Handshake、能力位、auth plugin 和受控认证错误。
- MongoDB：hello/isMaster、buildInfo 和受控认证响应。
- 每个适配器配套正常、畸形、慢速、超时、超限和回放样本。
- 管理台接入服务实例、端口、连接、事件和威胁清单页面。

### P2：复杂协议兼容

- MSSQL：TDS PreLogin、有限 Login 响应和 `sqlcmd` 阶段性验证。
- RDP：TPKT/X.224、TLS/NLA/CredSSP 分阶段验证，目标是 `mstsc` 到达握手或凭据阶段后受控结束。
- 增加拟真人格配置、客户端兼容性矩阵和证据详情。

### P3：扩展能力

- SSE/WebSocket 实时事件流；
- 适配器受信插件包和版本管理；
- 多节点 Sensor Agent 注册；
- 告警通道、威胁情报联动和受控自动阻断；
- 更高等级的有限交互，不执行真实命令或 SQL。

## 3. 一期数据建议

一期推荐使用隔离 SQLite WAL 保存事件、威胁聚合、配置版本和审计；通过 `IEventStore` 抽象存储实现，未来可以替换为 PostgreSQL、消息队列或集中事件平台。接入数据库前必须单独确认迁移、备份、留存和恢复方案。

默认建议：事件保存 30 天，原始密码和认证材料必须按字段白名单和大小上限采集并加密落盘，私钥不进入普通业务数据。ID 由注入的 `IIdGenerator` 生成，不在协议适配器中自造一套 ID。

## 4. 一期验收

- SSH 实例绑定 22/2222，两个端口都能握手，事件标记准确端口。
- TCP connect 后不发送数据即断开，仍能查询 `ConnectionAccepted`。
- 同一 IP 访问多个服务时，威胁档案只生成一条并保留服务/端口明细。
- 重复事件不重复增加计数，重启后不重复监听。
- 端口冲突、权限不足、握手超时、超大帧、连接超限和适配器异常可观测且有明确结果。
- 事件写入故障时展示队列、降级、丢弃/补偿和最后成功时间。
- SSH、MySQL、Mongo 完成约定 L1/L2 验证；RDP/MSSQL 只按已完成的阶段记录结果。

## 5. 明确不做

当前不开放公网监听，不连接真实数据库或桌面，不代理内部服务，不执行客户端命令，不自动修改宿主防火墙，不把 mock、静态页面或单次 telnet 连接当作协议兼容验收。
