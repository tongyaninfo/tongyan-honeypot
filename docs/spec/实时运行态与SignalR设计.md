# 实时运行态与 SignalR 设计

## 目标

运行总览、服务实例、威胁事件、威胁清单和认证证据页面在连接、认证事件、监听状态和活动连接数变化后自动刷新；断线时仍可通过 REST 快照继续使用。

## 鉴权边界

- Hub 地址为 `/hubs/honeypot`。
- 鉴权复用当前登录会话 token：HTTP 协商优先使用 `Authorization: Bearer`，浏览器 WebSocket 连接使用 SignalR 的 `access_token` 查询参数。
- `access_token` 只在 Hub 精确路径接受；不会被普通 API 当成登录凭据，也不写入本地持久化存储。
- 未初始化返回 `428 INITIAL_SETUP_REQUIRED`，无效或缺失 token 返回 `401 UNAUTHORIZED`。
- Hub 连接成功后仅服务已通过会话校验的管理台用户；退出登录后的新连接必须重新登录。

## 消息

| 消息 | 触发 | 内容 |
| --- | --- | --- |
| `eventAppended` | 事件存储成功 | 安全事件视图、来源 IP、端口、协议、结果、账号和证据 ID；不含密码原文 |
| `runtimeChanged` | 监听器状态、活动连接数或 accept/error 计数变化 | 监听器运行快照 |

事件广播是落库后的旁路动作，SignalR 发送失败不能阻断协议监听或事件记录。前端收到消息后重新拉取 REST 数据，避免只依赖推送消息造成断线期间的数据缺口；自动重连成功后也会补拉快照。

## 数据安全

原始密码、NTLM 响应、完整票据等认证材料只进入受控证据存储。SignalR 事件模型不包含 `Password` 字段，也不推送认证材料摘要；管理台需要取证时必须通过受保护的证据接口和审计流程。
