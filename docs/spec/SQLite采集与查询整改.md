# SQLite 采集与查询整改

本次范围为单机 SQLite、应用层 TCP 接纳和已解析的认证尝试。先在本地隔离环境实施和验收，目标环境的数据库迁移、程序切换另行确认。

## 存储与取证

- 库大小、行数、证据总字节和卷余量仅供观测。旧容量参数失效。存储层接受协议按输入边界实际采集的完整或截断材料。
- 每次已接纳的连接独立编号，准入拒绝有独立结果。每次认证按事件 ID、连接 ID 和序号关联。原始材料只保存在加密证据仓，受控原文读取先写审计。
- 写入成功以事务提交为准。重放、客户端取消和服务恢复不得造成重复认证或虚假的关闭记录。真实磁盘满、锁耗尽及 I/O 故障须能定位并暴露采集缺口。
- 连接摘要、认证和异常默认留存 30 天，证据沿用实例的有效期。仅新收到且明确属于正常协商的步骤短留 48 小时。事件计数、风险和报表先按真实步骤计算，报表白名单事实与运行采样默认保留 90 天。
- 首页接纳数采用近 24 小时，今日失败采用上海自然日。地图、计数和下钻读取索引字段，历史回填只使用有真实连接 ID 和序号的明细。

## 切换与回退

新增连接摘要与查询字段、索引的迁移仅在隔离数据目录验证。真实切换之前核验当前迁移、匹配的应用和证据密钥，停写并制作 SQLite 一致性备份，先从备份恢复验证。历史报告不能推导缺失的连接。应用降级时需使用能忽略新增结构且没有旧配额的版本，保留新数据和密钥；恢复旧备份需单独确认增量处置。

## 隔离验收

使用合成历史数据（65 万条明细、65 万条事实、7 万份证据）跨过旧配额，通过同一个 SQLite 文件执行实时写入、三套首页请求、月报、密码簿和清理。分别记录实际产生量、提交及可查询延迟、最终拒写、SQLite 锁重试、队列及逐连接和逐认证对账。持续阶段为每分钟 1,235 步、60 分钟，突发阶段为每分钟 2,470 步、15 分钟。接纳提交 P95 ≤ 500 毫秒、威胁可查和首页接口 P95 ≤ 1 秒，最终缺失或重复为零，突发结束后 60 秒内排空。另验重放、进程恢复、短留、低空间与真实 SQLite 满错误的区分。生产未切换前，上述验收只代表本地结果。
