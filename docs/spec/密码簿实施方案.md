# 密码簿实施方案

- 日期：2026-11-15
- 状态为已实现。持久化范围见[详细事件、威胁档案与密码簿持久化](连接事件与威胁清单设计.md#11-详细事件威胁档案与密码簿持久化)，配额与留存配置见[部署说明](../../deploy/README.md)。

## 菜单与统计口径

管理台新增「密码簿」，管理员可分页查看账号、密码、服务、认证次数和最近一次使用时间。按最近一次使用时间降序排列，同一时间按代表证据编号稳定排序。页面时间按 `Asia/Shanghai` 显示。当前页的密码逐条通过受控证据接口读取，返回后在密码列直接显示原文，每条读取均单独审计。

- 搜索对账号和服务做字面子串匹配，先筛选再分页，不需要读取密码原文。搜索条件不改变同组认证次数。
- CSV 导出读取所选搜索条件下的全部匹配页，按批次通过原文导出接口审计后提取密码。文件使用 UTF-8 BOM，包含账号、密码、服务、认证次数、最近使用时间（UTC）和取证状态。确实提交的空密码保留为空字段，通过取证状态与原文不可用的行区分。可能被识别为公式的单元格会在内容前加单引号按文本处理。[OWASP CSV Injection](https://community.owasp.org/attacks/CSV_Injection)

- 服务按协议类型归并，例如两个 SSH 监听实例中相同的账号和密码算作同一组合。账号和密码按证据中的实际文本区分大小写和空格，每个关联的认证事件计一次。最近一次使用时间取该组内最后一次认证尝试的事件时间。
- 纳入条件是同时启用了 `RecordUsername`、`RecordPassword` 和 `StoreCredentialEvidence`，认证失败事件已被接收，且关联的未过期证据明确包含实际提交的文本账号和密码，材料类型为 `Plaintext` 或 `Decrypted`。Redis 单参数 `AUTH` 的协议默认账号不会入簿；客户端显式提交 `default` 可正常入簿。
- 可确认实际提交的空密码正常入簿。InfluxDB v1 查询认证用证据标记区分省略 `p` 和显式 `p=`。二进制密码、缺失或为 `null` 的密码、另行请求变更的密码、令牌、票据、公钥和挑战响应均不进入密码簿。
- SSH 的 `password` 和密码式 `keyboard-interactive` 在当前实现中会记录客户端提交的密码，符合上述条件时可入簿。SSH 公钥认证、仅询问认证方法的连接以及其他没有文本密码的认证尝试均跳过。

## 存储与访问

- SQLite 保存 AES-GCM 证据密文。匹配认证事件时提取有界字段，以独立的持久密钥计算账号、密码和协议组合的 HMAC。指纹供服务端分组，索引保存账号展示值、事件时间和证据引用。密码原文留在加密证据中。
- 认证事件按 `EventId` 和 `CredentialArtifactId` 确认索引，两者同事务提交。只有证据写入而事件未确认的记录不计数，重发事件不会重复计数。索引与证据同步到期。分页查询按索引分组，无需解密其他页。
- 管理员分页接口使用 `ApiResult<T>`，返回账号、协议、次数、最近尝试时间和有效的代表证据引用。当前页逐条调用单条证据接口。服务端校验管理员身份和留存期限，访问审计写入 SQLite 后才返回原文，响应使用 `Cache-Control: no-store`。
- 次数覆盖所有仍在有效期内且已确认的证据。组内最后一条证据到期后整组从查询中消失。保留原数据库和证据密钥即可在新进程重查密码簿和证据。

## 验收与回滚

- 用合成输入验证同一组合多次尝试、不同密码、不同协议、显式空密码、InfluxDB 查询空值、没有密码的证据及禁用采集设置的统计结果。验证未确认或重复事件、证据过期和分页排序。
- 验证未登录与普通用户无法读取密码簿，管理员列表响应无密码原文和指纹。页面按条读取当前页的原文，直接显示且每条产生证据访问审计；切页、离开或证据过期后不保留已显示的原文。单条读取失败不影响同页其它条目。
- 实施后运行 `dotnet test backend/Honeypot.slnx`，并在 `frontend` 下运行 `npm run lint`、`npm test` 和 `npm run build`。本地验证使用隔离样本。
- 回退应用版本时保留数据库和对应的证据密钥，以便恢复后继续读取已收集的数据。
