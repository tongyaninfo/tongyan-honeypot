# 实时飞线地图实施方案

- 日期：2026-11-15
- 状态为已实现。底图来源、版本与许可见[世界底图来源](../../frontend/public/assets/maps/README.md)；部署侧落点配置与缓存策略见[部署说明](../../deploy/README.md)。

## 页面与观测口径

首页运行总览的「全球连接地图」默认展示当前实例最近 10 分钟接纳的连接，左下角可切换最近 60 秒、10 分钟、2 小时或 24 小时。用鼠标滚轮或触摸板围绕指针缩放，按住地图拖动。复位恢复全图位置，右上角支持进入和退出全屏。播放开关左侧为「暂停飞线」，右侧为「实时」，默认开启。打开地图或切换时间范围后先显示已有来源点。之后，新连接从来源点沿弧线飞向蜜罐部署位置，在目标点显示落地涟漪。飞线按监听服务类型配色。同一个连接只播放一次，握手、认证失败和断开等后续事件不重复触发。普通连接统一标为连接观测。

在同一画布内放大时，来源圆点和飞线移动点会适度缩小，来源点可悬停的范围保持原屏幕大小。蜜罐落点与涟漪也保持原屏幕大小，飞线仍按原地理坐标播放。

地图参考 WAF-Lite 的 `OverviewRequestMap.tsx` 和 `requestMapData.ts`。复用现有前端依赖 `d3` 和 `topojson-client`，用 Natural Earth 投影、SVG 底图和飞线动画。沿用 WAF-Lite 的 `world-110m.json`、版本 `world-atlas@2.0.2` 及同源静态资源路径，随资源附上 ISC 许可、Natural Earth 来源及校验值。运行时从本管理台加载底图。来源和许可的文本响应声明 `charset=utf-8`。

## 位置与数据

- 来源取总览近期事件快照中的 `ConnectionAccepted`，按事件发生时间筛选选中的窗口，并以 `ConnectionId` 去重。SQLite 先按接收时间读取仍有效的近期事件，受 `Honeypot:Events:MemoryEventCapacity` 和 `Honeypot:Events:MemoryRetentionHours` 约束，默认最多 20,000 条事件、最近 24 小时。快照容量包含其他事件步骤。采集量高时，即使仍可在历史事件列表查到较早的连接，地图也可能无法覆盖选中的整个时间段。
- 扩展 IP 定位结果，增加可空经纬度及来源版本。复用管理员当前已启用的数据源，支持 IP2Location（`ip2location`）、MaxMind GeoLite2 City（`geolite2`）和 DB-IP City Lite（`dbip`）。地点文本、经纬度、来源及版本取自同一次定位结果。经纬度必须同时存在、为有限数字且落在合法范围内，缺少坐标时不另查其他库。现有默认关闭、默认数据源 `CZ88` 及已保存设置沿用现状。关闭定位、无坐标、解析失败或为特殊用途地址时，只在覆盖统计中计数，不根据城市名估算坐标。
- 目标优先用 `Honeypot:AttackMap:Target` 配置的经纬度，其次是配置的公网入口 IP。未配置这两项且现有 IP 定位已开启时，由部署服务向同一定位服务探测公网出口 IP，并用当前选中的数据源定位。成功坐标缓存 1 天。同一目标切换定位设置或缓存到期时，后台重新查询。查询超时或失败时沿用上次成功的位置及时间，成功后更新。手动更换公网入口 IP 时按新目标查询。无可用位置时只显示来源点。出口 IP 只代表当前实例访问定位服务时的出口，在 NAT 或反向代理环境中可能与业务入口不同。
- 同源只读 `GET /api/v1/metrics/overview/connection-map` 沿用现有管理接口鉴权、`ApiResult<T>` 和 `Cache-Control: no-store`。服务端对窗口内的全部快照连接分类，按规范化 IP 去重查询归属地缓存，并复用现有 IP 归属地开关和后台队列。快照不包含认证账号、凭据和报文。

## 地点汇总与覆盖

- 每次地图快照检查所有候选公网 IP 的缓存和排队状态，新 IP 最多入队 128 个。达到本次入队额度或共享队列已满时，其余缺缓存地址等待后续快照入队。有缓存的地址仍参与本次统计。共享队列默认最多 1,024 个工作项、并发 4，缓存容量为 10,000 条。成功结果及失败结果分别缓存 24 小时和 1 分钟，设置变更会使来源缓存失效。请求不会等待上游解析。高流量时，等待定位的连接可能先移出窗口或近期快照。
- 窗口内取得有效坐标的连接全部计入 `origins`。默认按 0.01° 归并地点；超过 400 个来源点后逐级放大格网，最粗 15°，最多 325 个格。加粗后的格合并多个地点时标为「区域汇总」。每个格采用最近连接的位置和服务颜色，并显示连接数、不同来源 IP 总数及最多 12 个最近出现的不同来源 IP 和对应国家。
- `coverage.observed` 统计快照和窗口内的去重连接，分别归入已定位、归属未知、特殊用途地址和待定位。待定位包括已入队和等候入队，接口用 `coverage.deferred` 单独标记等候入队，页面可区分「定位中」和「等待定位」。没有有效坐标的连接参与统计。
- 接口继续返回最近 100 条已定位连接的 `events`，供实时飞线匹配及旧客户端使用。兼容字段 `coverage.omitted` 仅计入超过该列表容量的已定位连接；这些连接已计入来源汇总。页面用来源点的连接数和 IP 总数说明覆盖，用地点列出的 IP 数反映明细上限。

## 更新与降级

- 地图首次获取 REST 快照，随后复用首页现有 SignalR 连接。新接纳事件合并触发新快照，待定位时约每 1.5 秒补查，空闲时约每 5 秒刷新窗口。周期快照根据来源汇总更新地图，实时飞线仍匹配接到通知的近期连接。高流量下超出飞线样本或动效容量的连接仍可计入来源汇总。进程重启后来源缓存需要重新积累，近期事件由 SQLite 按快照限制读取。
- 客户端按连接标识去重，只为基线快照后接纳的连接播放飞线。基线之前的连接后来补齐坐标时，只更新来源点。后台页面停止轮询和动画，回到页面时先建立新基线。支持暂停动效和系统减少动态效果偏好。动画上限为同时 32 条，等待队列最多 200 条，过量时保留基础地图和来源点。缺失目标、底图加载异常、断线或查询失败时停止播放，按原因显示降级状态。鉴权失效时清空地图数据。
- 改动范围是总览地图和同源静态资源、地图查询、现有归属地结果的可空字段，以及部署目标的可选配置。沿用当前事件存储、数据库结构、协议监听和 IP 配置。验证使用隔离环境和合成数据。

## 验收与回滚

- 后端用合成事件验证四档时间窗、连接和 IP 去重、非接纳事件不绘制、分批入队及等待统计。超过原候选限额或飞线样本容量时，检查已定位连接是否仍计入来源汇总，并匹配格网和 IP 清单数量。用模拟定位响应验证同源坐标、合法零值、缺失或非法坐标、私网、解析关闭、目标坐标优先和公网入口 IP 覆盖。检查已定位条目的来源 IP 和国家字段，并验证登录校验与凭据隔离。
- 前端测试首次快照只显示来源、来源汇总独立于飞线列表、刷新只播放新连接、待定位区分、目标不可用时保留来源点、暂停后恢复及断线状态。在真实浏览器验证桌面和窄屏的地图对齐、浅色和深色、鼠标操作及减少动态效果。
- 实施后运行 `dotnet test backend/Honeypot.slnx`，并在 `frontend` 运行 `npm run lint`、`npm test` 和 `npm run build`。核对构建产物包含固定底图和许可，检查页面加载只访问同源地图资源。
- 如需回滚，撤回地图组件、接口及地图配置的代码，归属地的可空字段可独立保留或随实现撤回。无需迁移、重写事件或调整监听。
