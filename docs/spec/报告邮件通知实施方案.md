# 报告邮件通知实施方案

更新日期：2026-11-10。状态：功能已实现，已完成自动化测试与隔离迁移验证。本方案包含下列六张表及隔离临时 SQLite 迁移测试；现有运行库迁移与部署不在本次范围内。实际验证结果见发布说明。

## 范围

只实现日报、周报、月报邮件通知，不增加登录、封禁或解封事件通知。蜜罐认证尝试及失败仍是运行报告的统计维度。系统管理增加通知设置和邮件记录，新增运行报告页面。

通知设置包含 SMTP 主机、端口、默认勾选的 SSL/TLS、隐式 TLS 或强制 STARTTLS、发件邮箱与名称、登录账号、授权码、超时、默认收件人及发送频率。日报、周报、月报独立配置收件人和北京时间发送时间；周报固定周一，月报固定每月一日。默认均为 08:00，自动通知初始关闭。

## 数据库变更清单

使用现有 EF Core SQLite 和数据目录，不引入外部数据库。仅新增以下六张表及必要索引，不删除表、不改写原实例和监听器记录。

| 新表 | 内容与约束 |
| --- | --- |
| `report_events` | 报告统计事实；事件 ID 唯一；UTC 时间、来源、协议、端口、事件类型、认证失败标记、用户名/认证方法及证据元数据等白名单字段；按时间和来源查询。不是完整交互事件副本，不保存密码、原始认证材料及任意原始 payload。 |
| `report_source_first_seen` | 规范化来源 IP 主键与首次被采集时间，用于跨周期新增来源统计，避免将每次重启误认作新来源。 |
| `report_runtime_samples` | UTC 采集心跳、应运行/实际监听状态、活动连接、进程 CPU/工作集及可用资源采样；保留采集故障计数和未知时段，不把缺失时间当正常运行。 |
| `report_snapshots` | 已生成报告的周期、生成时间、统计 JSON 快照和自动调度唯一键；同一自动周期只创建一次，历史正文与数据不随未来变化。 |
| `email_deliveries` | 每个收件人一条发送任务；唯一业务键、报告关联、主题/HTML/纯文本快照、状态、租约、重试时间及脱敏失败信息。 |
| `email_delivery_attempts` | 每次 SMTP 尝试的开始/结束时间、结果和脱敏错误，关联发送任务；不保存 SMTP 认证正文。 |

配置放运行时受控 JSON，不写入仓库配置或 `.env`。SMTP 授权码以 AES-GCM 密文保存；持久化保护密钥放独立目录并限制文件权限，只在首次保存授权码时创建。接口读取仅返回 `hasCredential`，留空表示保留原授权码。密钥缺失不得悄悄覆盖或回退明文。

新通知与报告资源通过统一 `IResourceIdGenerator` 生成字符串 ID，保留接入集中 ID 服务的替换入口。

## 接口合同

HTTP 业务返回统一 `ApiResult<T>`，列表包含 items/total/page/pageSize；失败保留真实 HTTP 状态。通知管理、发件操作和历史邮件只允许管理员。

| 接口 | 用途 |
| --- | --- |
| `GET/PUT /api/v1/settings/notifications` | 读取/保存邮件与订阅配置；PUT 使用 settings 和只写 authorizationCode。 |
| `POST /api/v1/notifications/test` | 使用已保存配置，为指定 recipient 创建测试任务。 |
| `GET /api/v1/notifications/emails` | 按 kind/status/recipient/fromUtc/toUtc 查询并分页。 |
| `GET /api/v1/notifications/emails/{id}` | 正文快照、尝试记录和是否允许重发。 |
| `POST /api/v1/notifications/emails/{id}/retry` | 手动重发，保留历史并检查冷却与配额。 |
| `GET /api/v1/reports` | period=day/week/month/custom；custom 需 startAtUtc/endAtUtc，最长 366 天。 |
| `POST /api/v1/reports/send` | period/startAtUtc/endAtUtc/recipients，为当前选择周期生成快照并排队。 |
| `GET /api/v1/reports/history` | 已生成历史报告分页。 |
| `GET /api/v1/reports/history/{id}` | 读取报告生成时的冻结数据。 |

## 统计口径

- 日/周/月按 Asia/Shanghai 自然周期解释；内部查询 UTC 半开区间 `[start,end)`。当前周期与上一周期按相同已过时长比较。完整日报统计昨天，周报统计上周，月报统计上月。
- 连接数只数 ConnectionAccepted；认证尝试与连接分开计数，失败包含 failure/rejected/invalid。不能将握手步骤数当攻击次数。
- 独立来源按整个选定周期去重，不能相加每日去重数；新增来源依据持久化首次观测时间。
- 统计连接、认证、协议/端口/来源/用户名/认证方法排行、协议异常、风险增量、证据摘要、运行资源和采集覆盖度。无法采集的字段显示未知，不伪造 0。
- 本次持久化只保证报告元数据；当前原始认证证据仍受现有存储和留存限制，不能把报告上线声称为生产级证据仓库完成。
- 上线前丢失的内存历史无法补回；采集覆盖度随采样明确显示，缺失时段保留未知。

## 调度与邮件投递

SQLite 保存任务和业务去重键，BackgroundService 串行执行发送，不在登录或协议处理中访问 SMTP。发送窗口、已发送数量、冷却根据持久化记录判定；测试和重发也受配额控制。

发送状态使用 Pending/Sending/Accepted/Retrying/Failed/Unknown。Accepted 仅代表 SMTP 受理，不能代表已到达或已读；提交后断线、受理后落库前崩溃等情况保留 Unknown，不自动重发。普通 SMTP 无法保证恰好一次投递。明确临时失败采用有限重试。

首次启用不补发启用前的旧任务；已启用的计划停机恢复后只补最近一个应执行完整周期。周期唯一键避免重启重复发报。已入队任务保留收件人与正文快照；关闭总开关暂停新的外发。

## 模板和页面

HTML 模板在 `backend/src/Honeypot.Api/Resources/EmailTemplates/`，文件为 `Layout.html`、`Test.html`、`Daily.html`、`Weekly.html`、`Monthly.html`，随发布复制。采用约 680px 邮件宽度、品牌蓝、白底卡片、风险强调、核心指标和 Top 排行；内联 CSS、表格布局、纯文本备选。所有用户与攻击者可控文字必须编码，不加入脚本、密码、票据、Token 或访问凭据链接。

管理台沿用 Ant Design 主题和图表。通知设置分“邮件服务器”和“报告订阅”；报告包含指标卡、趋势、排行、运行采样及覆盖度提示；邮件详情在禁止脚本和外部资源的隔离容器预览。

## 验证与回滚

隔离临时 SQLite 验证新增迁移与既有配置保留、事件去重、整期来源去重、日周月边界、重启恢复、冻结快照与队列状态。测试传输使用本机隔离 SMTP 或替身，不使用真实收件人，不读取生产密钥。验证 TLS 配置、授权码保护、HTML 编码、管理员鉴权、配额与不确定结果处理。

运行后端测试及前端 lint/test/build；检查发布输出包含 HTML 资源。真实邮件供应商收信、目标邮箱布局和实际服务器性能需要部署后单独验证。

回滚先关闭通知总开关/调度，再切回旧应用。新增表和报告数据保留，不执行删表或文件清理。数据库文件备份和实际部署迁移须在明确授权环境执行；本次不部署、不操作 Git、不改现有 `.env` 或真实密钥。
